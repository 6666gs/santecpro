# MPM-211 多量程拼接

## 官方依据

[官方 C# 示例 Form1.cs](https://github.com/santec-corporation/VS_IL_Sample/blob/main/VS_IL_Sample/ILSTS_Sample_CS/Form1.cs) 的 `btnmeas_Click` 遍历 `Meas_rang`：设置 MPM Range、扫描、读取数据，完成后重采样并调用 `Cal_IL_Merge(Module_Type.MPM_211)`。其 Reference 示例只扫描一档。核对的 VS 仓库提交为 `497b8a18929b894ec835fcbb301e7f30d5acc841`。

另外静态核对了项目附带的 `STSProcess.dll` 2.2.7 中 `Range_Threshold.MergeData`、`GetRangeThreshold` 以及排序比较器的 IL；没有连接仪器运行 DLL。MPM_211 枚举值为 1，对应上限数组为 `[10, 0, -10, -20, -30] dBm`。

## 本项目规则

量程编号升序：先拷贝第一档的功率谱，然后对每个更灵敏的档位，仅在“当前已拼接功率 **严格小于** 新档位上限”的波长点替换功率。恰好等于上限时保留前一档。各通道独立判断，Monitor 保留第一遍扫描（与上述官方 Raw 合并规则一致）。不做均值、平滑、额外 Monitor 归一化或偏移补偿。

这是将核对到的官方 Raw 阈值算法重现为 Python；没有直接调用会连同 Reference/Monitor 计算 IL 的 `Cal_IL_Merge`。因此保留用户定义的 Loss = measure − reference。当前只对 MPM-211 声明支持，其他模块需要对应型号的阈值。

服务器逐档合并，不长期持有所有档位的完整谱。只接受完全相同的波长网格和通道，以及有限值；不对不同网格插值、不伪造缺失点。返回量程清单、算法名和各通道来自各档位的点数统计（`range_merge_source_counts`）；CSV 记录量程清单和算法名，数据列仍为最终拼接谱。独立量程原始谱不随拼接 CSV 保存，需要排查接缝时可另做各档单量程扫描。

## 使用边界

Range 2、3、4、5 可覆盖强弱差异较大的器件谱；如果有超过 Range 2 上限的信号，需包含 Range 1。顺序扫描期间必须保持光路、偏振和器件状态稳定，拼接不能消除两次扫描之间的变化。

官方阈值算法并不保证所有点都在有效测量区间：超出所选档位总能力、噪声底或饱和的平台依然可能出现在输出中。本实现也不把这些有限值自动替换为虚构数据或承诺“扩展了仪器物理极限”。接缝处的准确性仍需实机对照单档扫描确认。

## 验证

使用模拟数据验证阈值边界、多通道、正反波长网格、错误网格/数据、HTTP 整组取消和失败处理、脚本范围参数、旧服务检测、Raw 导出后重新导入，以及现有 UI 布局与扫描流程回归。未执行真实硬件扫描。
